## Evaluation Workflow

The current evaluation workflow is driven by:

- [main/evaluator.py](main/evaluator.py)
- [main/util.py](main/util.py)
- [results/ResultsNB.ipynb](results/ResultsNB.ipynb)

If you want the full comparison results, the execution order is:

1. run [main/evaluator.py](main/evaluator.py)
2. then run [results/ResultsNB.ipynb](results/ResultsNB.ipynb)

This order is required because the notebook consumes the CSV files generated by the evaluator.

## `MDP_Dataset_Builder` Configuration

The evaluator can optionally post-process generated adaptations through `MDP_Dataset_Builder`, so the selected domain configuration must be aligned with the dataset being used.

Important: the `config.py` file for the domain you want to use must be present in:

`MDP_Dataset_Builder/config.py`

and not only inside a domain-specific subfolder such as:

- `MDP_Dataset_Builder/UAV_v02/config.py`
- `MDP_Dataset_Builder/AutonomousDriving_v1/config.py`

The evaluation utilities load the builder configuration to:

- read `SS_VARIABLES`
- read `CONSTRAINTS`
- validate feature names and feature order
- validate the number of input features
- coerce adaptation values to the declared feature domains
- execute builder-based evaluation on generated adaptation datasets

If the dataset and the active builder config refer to different domains, the evaluation phase may fail or produce invalid outcomes.

## Path Logic in `main/util.py`

The main path-related logic is implemented in [main/util.py](main/util.py).

### Dataset paths

`get_evaluator_domain_config(...)` currently maps:

- `UAV_v02` -> `../datasets/uav.csv`
- `RescueRobot` -> `../datasets/balanced_dataset2.csv`

`main/evaluator.py` uses this mapping to select the dataset for the current domain.

### Results directory

The results folder is generated with:

```python
build_results_dir(dataset_path)
```

which resolves to:

```python
Path("../results/WIP_only_true") / Path(dataset_path).stem
```

Examples:

- `../datasets/uav.csv` -> `../results/WIP_only_true/uav`
- `../datasets/balanced_dataset2.csv` -> `../results/WIP_only_true/balanced_dataset2`

### Builder directory

The default builder location is:

```python
BUILDER_DIR = PROJECT_ROOT / "MDP_Dataset_Builder"
```

### Default results root

The default results root is:

```python
RESULTS_DIR = PROJECT_ROOT / "results/WIP_only_true"
```

### Explainability and anchor outputs

`util.py` also defines helper logic for:

- explainability plots folders
- anchor explanations and rules folders under `main/polytopes/WIP_only_true/...`

These are used by the WIP and Anchors workflows.

## What `main/evaluator.py` Does

[main/evaluator.py](main/evaluator.py) is the main experiment driver. It:

1. selects the active domain through `mdpDomain`
2. loads domain metadata through `get_evaluator_domain_config(...)`
3. loads the dataset CSV
4. validates feature names against `MDP_Dataset_Builder` when `evaluate = True`
5. splits the dataset into training and test sets
6. trains one classifier per requirement
7. instantiates the planners:
   - `CustomPlanner`
   - `NSGA3Planner`
   - `WIPPlanner`
   - `AnchorsPlanner`
8. runs the planners on the selected test samples
9. stores adaptations, confidences, scores, timings, speed-ups, and iteration counters
10. writes result files
11. optionally evaluates the generated adaptations through `evaluateAdaptations(...)`

### Main configuration points in `main/evaluator.py`

The most relevant parameters are:

- `evaluate`
- `mdpDomain`
- `n_neighbors`
- `n_startingSolutions`
- `targetConfidence`
- `testNum`

## Files Produced by the Evaluator

Inside the dataset-specific results folder, the evaluator produces at least:

- `X_train.csv`
- `X_test_evaluated.csv`
- `results.csv`

If `evaluate = True`, it also generates:

- `nsga3Dataset.csv`
- `customDataset.csv`
- `anchorsDataset.csv`
- `wipDataset.csv`

These four files are produced by evaluating the generated adaptations with `MDP_Dataset_Builder`.

## How `evaluateAdaptations(...)` Works

The post-processing logic is implemented in [main/util.py](main/util.py).

`evaluateAdaptations(...)`:

1. extracts adaptation vectors from `results.csv`
2. builds four tabular datasets:
   - NSGA-III adaptations
   - XDA / CustomPlanner adaptations
   - Anchors adaptations
   - WIP adaptations
3. passes each dataset to `evaluateDataset(...)`

`evaluateDataset(...)` then:

1. validates the dataset structure against `SS_VARIABLES`
2. coerces values to the builder-defined domains
3. writes the dataset to `MDP_Dataset_Builder/starting_combinations.npy`
4. launches parallel builder jobs through `MDP_Dataset_Builder/main.py`
5. merges partial outputs through `merge_csvs.py`
6. moves the merged CSV into the selected results directory

So:

- `results.csv` contains planner-side metrics
- `customDataset.csv`, `nsga3Dataset.csv`, `anchorsDataset.csv`, and `wipDataset.csv` contain builder-evaluated outcomes

## How to Run the Workflow

### Step 1: select the domain

Inside [main/evaluator.py](main/evaluator.py), set:

- `mdpDomain = "RescueRobot"` or `mdpDomain = "UAV_v02"`

and verify that the corresponding dataset path is correct.

Also make sure the active domain configuration is available in:

`MDP_Dataset_Builder/config.py`

### Step 2: run the evaluator

```bash
python main/evaluator.py
```

### Step 3: inspect generated outputs

Check:

```text
results/WIP_only_true/<dataset_stem>/
```

You should find `results.csv` and, if evaluation is enabled, the four evaluated adaptation datasets.

### Step 4: run the notebook

Open [results/ResultsNB.ipynb](results/ResultsNB.ipynb), set:

- `DOMAIN`
- `resultsFolderPath`

and then execute the notebook cells.

The notebook:

1. loads `results.csv`
2. loads `customDataset.csv`, `nsga3Dataset.csv`, `anchorsDataset.csv`, and `wipDataset.csv`
3. expands confidence arrays into columns
4. computes plots and aggregate metrics

## Common Pitfalls

- The dataset domain and `MDP_Dataset_Builder/config.py` do not match.
- The domain config exists only in a domain subfolder and not in `MDP_Dataset_Builder/config.py`.
- `resultsFolderPath` in `ResultsNB.ipynb` points to the wrong output folder.
- The notebook is run before `main/evaluator.py`.
- Feature names match semantically but not in exact order.

## How to Extend the Tool

This repository can be extended in two common directions:

1. adding a new planner to the comparison
2. adding a new domain on which to run the experiments

### Add a New Planner

If you want to compare an additional planner, the required operations are:

1. Create the planner implementation in `main/`.
   The new planner should expose an interface compatible with the current evaluation loop, ideally returning:
   - the final adaptation
   - the confidence vector
   - the optimization score
   - optional extra metadata such as iteration count

2. Import the planner in [main/evaluator.py](main/evaluator.py).

3. Instantiate the planner in the evaluator together with:
   - `CustomPlanner`
   - `NSGA3Planner`
   - `WIPPlanner`
   - `AnchorsPlanner`

4. Add the planner execution block inside the test loop in `main/evaluator.py`.
   This usually means:
   - calling the planner on each test sample
   - measuring execution time
   - computing or storing its score
   - optionally generating explainability artifacts if needed

5. Extend the `results` rows collected by the evaluator.
   You must add the new planner outputs to the list appended inside the main evaluation loop.

6. Extend the final `results.csv` schema in `main/evaluator.py`.
   Add new columns for:
   - adaptation
   - confidence
   - score
   - execution time
   - any planner-specific metrics

7. Extend [main/util.py](main/util.py) if you also want builder-based outcome evaluation for the new planner.
   In practice, this means updating `evaluateAdaptations(...)` so it:
   - extracts the new planner adaptation vectors from `results.csv`
   - builds a dataframe with the same feature columns
   - calls `evaluateDataset(...)` for that new adaptation set

8. Update [results/ResultsNB.ipynb](results/ResultsNB.ipynb).
   The notebook currently assumes four planners, so you need to update:
   - the input CSV loading section
   - the confidence dataframe construction
   - the outcome dataframe construction
   - score and timing tables
   - legends, labels, and plotting helpers
   - any hardcoded assumptions such as the number of algorithms per requirement

9. Update the documentation.
   Add the new planner to:
   - this `README.md`
   - the notebook labels
   - any technical comparison document if needed

### Add a New Domain

If you want to run the experiments on a new domain, the required operations are:

1. Create or prepare the domain dataset.
   The dataset must contain:
   - all feature columns in the correct order
   - one binary requirement column for each requirement to learn and evaluate

2. Create the domain configuration for `MDP_Dataset_Builder`.
   At minimum, the builder configuration must define:
   - `SS_VARIABLES`
   - `CONSTRAINTS`

3. Make the domain configuration active in:

   `MDP_Dataset_Builder/config.py`

   This is required for the current evaluation pipeline. It is not sufficient to keep the config only in a domain-specific folder.

4. If desired, also keep a domain-specific copy in a subfolder such as:
   - `MDP_Dataset_Builder/<NewDomain>/config.py`

   but before running the evaluator, ensure that the active configuration exposed at `MDP_Dataset_Builder/config.py` is the one matching the dataset under test.

5. Extend `get_evaluator_domain_config(...)` in [main/util.py](main/util.py).
   Add a new entry to `domain_defaults` with:
   - `dataset_path`
   - `controllable_feature_indices`
   - `optimization_directions`

6. Verify that the builder config and evaluator assumptions are consistent.
   In particular:
   - `SS_VARIABLES` order must match the dataset feature order
   - the number of requirements implied by `CONSTRAINTS` must match the requirement columns you expect
   - the controllable feature indices must refer to valid features

7. Make sure `get_evaluator_domain_config(...)` can derive:
   - `feature_names`
   - `controllable_feature_names`
   - `external_feature_names`
   - `reqs`

   These values are computed from the active builder config plus the domain defaults.

8. Update [main/evaluator.py](main/evaluator.py) to select the new domain through `mdpDomain`.

9. If the notebook uses hardcoded labels for that domain, update [results/ResultsNB.ipynb](results/ResultsNB.ipynb).
   In particular, add the new domain profile to the notebook configuration section if you want domain-specific:
   - feature names
   - requirement names
   - plot labels

10. Run the evaluator and verify the output files.
   At minimum, check that the new domain generates:
   - `results.csv`
   - `X_train.csv`
   - `X_test_evaluated.csv`
   - builder-evaluated adaptation datasets if `evaluate = True`

11. Validate the domain end to end.
   A good final check is:
   - run `python main/evaluator.py`
   - confirm that `validateBuilderFeatureNames(...)` passes
   - confirm that the builder evaluation phase completes
   - run `ResultsNB.ipynb` on the new results folder

### Recommended Checklist

When extending the repository, a safe order is:

1. make the code changes
2. run `main/evaluator.py`
3. confirm that the expected CSV files are generated
4. run `results/ResultsNB.ipynb`
5. only then update plots, tables, and documentation if anything still assumes the old planners or domains

## Planner Notes

For the conceptual comparison between `CustomPlanner` and the PDP fallback used in `WIP.py`, see:
- [docs/customplanner_wip_comparison_en.md](docs/customplanner_wip_comparison_en.md)

Current `WIPPlanner` note:

- the anchor/polytope path remains the primary adaptation route;
- the PDP fallback is now a small multi-seed search rather than a pure single-start greedy walk;
- it generates candidate seeds from local summary-PDP maxima around nearby KNN neighbors;
- it ranks those seeds using confidence and `optimizationScoreFunction`;
- it refines only the best seeds with the existing greedy PDP step.
